A scheduled Scan emits neither, since no one asked for it. `scan_quota_reached` fires only on the `quota` authorization status, which `decideManualScan` returns exactly when a non-admin owner is past their daily limit *and* has no payment method — an owner with a card on file bills the extra Scan as overage and emits `scan_requested` instead. That makes it a true paywall encounter rather than a generic refusal, which is the most actionable conversion signal the app has.
- [x] 12.16 Split the Scan pipeline into stage-owned folders (owner-requested). `worker/review/track.ts` was doing two jobs, so it split: `worker/budget.ts` holds the Scan's money (`Budget`, `StageCosts`, `charge`, `canSpend`, the cost rates) and `worker/review/outcomes.ts` keeps the review-only tallies. That fixed two backwards imports that existed before — `scan.ts` reached into `review/track` to charge *ingestion*, and `telemetry.ts` imported `Budget` from the review module despite having nothing to do with review. `worker/ingesters/` then became `worker/ingest/`, gaining an `index.ts` that exports `ingestFromTopicSources()` mirroring `reviewScan()`, and absorbing `ingestFromSource`, `toScanSummary`, the `traceStage("ingest")` block, and the Resource insert from `scan.ts`. Net: `scan.ts` drops from 244 to ~140 lines and reads as pure orchestration, and "where does ingestion happen" has a one-place answer for the first time.
- [x] 12.12 Close the console-breadcrumb leak and make an email failure debuggable (owner-requested). The email report deliberately excluded the recipient, but `consoleIntegration` ships in `@sentry/bun`'s defaults and turns every `console.error` into a breadcrumb attached to the next event — and `scrubContent` only rewrites `extra` and `contexts`, never `breadcrumbs` — so the address logged one line above reached Sentry anyway. Fixed at both ends: `scrubBreadcrumb` drops console breadcrumbs in `beforeBreadcrumb` (the sdk's own request breadcrumbs survive), and `worker/email.ts` now names the recipient's domain rather than the address, in the logs as well as the report. The report also gained `emailKind` (`verification`, `topic-scan`, `manual-scan`, passed by all three call sites) so a blocked signup groups apart from one missed digest, and `resendError`, the `name` out of Resend's JSON body — the body's `message` is left behind because a validation error can quote the address back. Headers stay out entirely: `List-Unsubscribe` carries a signed one-click token, which is a credential. The accepted-id read is now non-fatal, so a 2xx Resend answers with an unreadable body can no longer report a send that actually succeeded.
