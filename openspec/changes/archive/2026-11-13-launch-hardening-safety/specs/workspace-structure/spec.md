## MODIFIED Requirements

### Requirement: One Bun version is pinned everywhere, and the lockfile is written by it

`.bun-version`, both `oven/bun` stages of the Dockerfile by tag and digest, the `@types/bun` range, and the `bunx bun@`
pin in the README SHALL name the same Bun version, the one the Dockerfile's tag names, and `bun.lock` SHALL be
regenerated by that version after the package.json files split. CI SHALL keep reading the version from `.bun-version`
through `.github/actions/setup-bun`. A preflight check SHALL fail if `.bun-version` differs from the Dockerfile's
tag.

#### Scenario: CI and the image run the same Bun

- **WHEN** CI installs Bun from `.bun-version` and the image builds from its `FROM` lines
- **THEN** both run the same version, and the frozen install reads the lockfile without rewriting it

#### Scenario: A moved image tag fails preflight

- **WHEN** an update moves the Dockerfile's `oven/bun` tag and leaves `.bun-version` as it was
- **THEN** the preflight check fails naming both versions
