# Release checklist

The acceptance list a store release of the CarlNotes app passes. Copy the table into the release record, fill the
result, date, and checked-by cells as each item runs, and keep this file's cells at `unverified`. An item that did not
run is named in the release record as unverified. It is never marked passed, and the release notes say which items
were skipped and why.

| Item | How to check | Result | Date | Checked by |
| --- | --- | --- | --- | --- |
| Phones in portrait with the keyboard | On an iPhone SE, an iPhone with a Dynamic Island, and a small Android phone, open Home, a Topic, a chat room, a note, the Account form, and the sign-up form. Open the keyboard on every composer and field. The composer, the Send button, the Done control, and the player dock stay reachable and nothing sits behind the keyboard | unverified | | |
| Tablets in both orientations with the keyboard | On an iPad and an Android tablet, repeat the phone pass in portrait and landscape. The app config locks phones to portrait, so landscape is a tablet check. The wide Podcast Episode page shows its chapter table and the extra cover | unverified | | |

| Larger text | Set the largest accessibility text size (iOS Settings, Accessibility, Display and Text Size, Larger Text at the top of the slider; Android Font size at the maximum). Every screen scrolls, no label truncates a count or a button, the mention suggestion and Send stay reachable on the iPhone SE, and the plan cards and the spend meter wrap | unverified | | |
| Light and dark palettes | Switch the device appearance and the menu's Light mode and Dark mode items. Every screen, sheet, badge, and the splash use the palette, with no light surface left in dark and no dark text on dark | unverified | | |

| Push permission and the sheet | On a fresh install of each platform, launch and confirm no notification prompt shows. Follow a first Topic: the "Turn on notifications?" sheet explains both kinds, and the system prompt shows only after Turn on notifications. On another fresh install, choose Not now, and confirm the sheet never shows again and Account offers Turn on notifications | unverified | | |
| Push denial and settings guidance | Deny the system prompt. Account's Notifications section shows both switches off and disabled, says notifications are off in the phone's settings, and Open settings opens the app's system settings. Allow notifications there, return, and the switches enable at their saved values. On iOS, an install upgraded from a badge-only build shows the same guidance | unverified | | |
| Push delivery and opening | With `EXPO_PUSH_ACCESS_TOKEN` set and enhanced push security on, run a scheduled scan that keeps new findings on a followed Topic, and have a second account mention the first in a Topic room and the Team room. Open each push with the app in the foreground, in the background, and closed: each opens its Topic or room. A mention for the room on screen shows no banner | unverified | | |
| Push sign-out and a second account | Sign out on a registered phone, then mention that account from another: nothing arrives. Sign in as a second account on the same phone and mention the first account: nothing arrives, and the second account's own mentions do | unverified | | |
| Push credentials | `eas credentials` shows an APNs key for iOS and an FCM V1 service account key for Android, and the build used `GOOGLE_SERVICES_JSON` | unverified | | |
| Spoken questions and answers | On one phone at a time, never two devices recording in the same room: the first mic tap shows the system's microphone prompt with the purpose line, and a denial shows Carl's words with Open settings. The podcast mic in the dock and the card pauses the podcast episode, the chapter line reads Listening, Thinking, then the host, and the podcast episode resumes. A call, a removed headset, and the lock screen pause the answer, and backgrounding ends a recording. After sign-out the app's cache holds no `spoken-part-*` or `voice-recording-*` file | unverified | | |
