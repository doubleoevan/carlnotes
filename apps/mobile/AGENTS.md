# apps/mobile

The Expo app: CarlNotes for iOS and Android from one codebase, on a development build, never Expo Go. It depends on the
universal packages alone — `@carlnotes/contracts`, `@carlnotes/client`, `@carlnotes/core`, `@carlnotes/nightshift` —
and the package boundary check fails anything else, a type-only import of `@carlnotes/api` included.

## Layout

- `app/` — the Expo Router routes. `_layout.tsx` loads the fonts behind the splash screen, configures the api client,
  and stacks the providers: PostHog, the TanStack Query client, and Sentry's wrap. `index.tsx` is the root screen. A
  route's component is a screen (`HomeScreen`), the native word for what the web calls a page.
- `src/` — the app's own modules: `apiBaseUrl.ts` chooses the api url, `typeRoleStyles.ts` maps the Nightshift type
  roles to native text styles. Pure logic with `bun test` coverage beside it; no test renders a React Native component.
- `global.css` — the stylesheet: tailwind, uniwind, and `@carlnotes/nightshift/uniwind.css`, the theme Nightshift
  writes. Change a token in `packages/nightshift/`, never here.
- `metro.config.js` — Sentry's base config inside `withUniwindConfig`, which must stay the outermost wrapper. Expo
  configures Metro for the monorepo and Bun's isolated install on its own, so add no watchFolders and no resolver
  aliases.
- `uniwind-types.d.ts` — generated by Uniwind from the theme, committed like the web app's route tree. Regenerate with
  the dev server, never edit it.
- `app.config.ts` — the identity, the EAS project link, and the Sentry and splash screen plugins. `eas.json` — the
  build profiles, each pinned to Bun 1.4.3 and an EAS environment. EAS is Expo Application Services, the vendor's name
  for its cloud build and update services, so identifiers and files keep its word.

## Commands

- `bun run dev:mobile` — the Expo dev server under Doppler's dev config, with the expo-mcp server on, from the repo
  root.
- `bun run mobile:build -- --profile development-simulator` — an EAS cloud build; profiles: development,
  development-simulator, preview, production.
- `bun run mobile:update` — an EAS Update on the fingerprint runtime policy.
- `bun run mobile:env:sync` — moves the mobile values from Doppler into the EAS environments. Never type a value into
  the EAS dashboard.
- CI exports both platforms' bundles (`expo export`) to prove Metro resolves the isolated install; preflight does not,
  because the bundle takes minutes.

## The api in development

`apiBaseUrl.ts` points the client at port 3000 on the host the device reached the dev server on, so the iOS simulator,
the Android emulator, and a phone on the same network all reach `bun run dev:api` with no setting. The one gap is a
USB-connected Android device in localhost mode, which needs `adb reverse tcp:3000 tcp:3000`.

## Accessibility bar

Every mobile change holds to the bar the web's Storybook checks set:

- Every pressable control has an `accessibilityLabel` and an `accessibilityRole`.
- Text scales with the system's text size on iOS and Android without clipping. Leave `allowFontScaling` on.
- Touch targets are at least 44 points.
- Colors come from Nightshift through Uniwind utilities (`bg-primary`, `text-muted-foreground`), whose contrast test
  already holds text to WCAG AA. No literal color values.
- Type goes through the roles in `src/typeRoleStyles.ts`, so a role reads the same on both platforms.

## Values

The app reads `EXPO_PUBLIC_SENTRY_DSN` and `EXPO_PUBLIC_POSTHOG_KEY`, inlined by Metro, and an EAS build reads
`SENTRY_AUTH_TOKEN` to upload source maps. All three live in Doppler (dev and prd) and reach EAS through
`mobile:env:sync`. A reporter without its key stays off, so a build without keys sends nothing.
